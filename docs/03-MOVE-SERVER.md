# 🚚 النقل من سيرفر لسيرفر

## المبدأ الأساسي (افهمه مرة واحدة)

التطبيق = **صندوق Docker واحد + قائمة متغيرات + قاعدة بيانات خارجية (Turso)**.
مفيش أي حاجة مربوطة بـ Render نفسها — النقل معناه: انشر نفس الريبو في مكان تاني.

```
الكود (GitHub) ──► أي مضيف (Render / VPS / Railway / Fly / جهازك)
المتغيرات ──────► تتنسخ بإيدك (الأسرار مش في الكود عن قصد — أمان)
الداتا ─────────► على Turso — السيرفر الجديد بيشوفها فورًا بنفس المفتاحين
```

## ✅ Checklist النقل الكامل

1. **جهّز المضيف الجديد:** أي حاجة بتشغّل Docker (Render / Railway / Fly.io / VPS
   عليه Docker). الأمر الوحيد اللي محتاجه: `node --experimental-sqlite` —
   وده متظبط جوه `Dockerfile` و `render.yaml` أصلًا.
2. **انسخ الأسرار دي بإيدك** من لوحة Render للمضيف الجديد (دي مش في GitHub):
   - `EF_SECRET` ⚠️ **لازم يتنقل زي ما هو بالظبط** — لو اتغيّر، كل المستخدمين
     هيتطلعوا ويسجلوا من الأول
   - `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN`
   - `REDIS_URL` (لو مفعّل)
   - `EF_MAIL_API_URL` / `EF_MAIL_API_KEY` / `EF_MAIL_FROM`
3. **اضبط `EF_BASE_URL`** على الرابط الجديد (مهم لروابط إيميلات التحقق).
4. **انشر** — أول ما يقلع، افتح `/api/health`: المفروض `turso-remote` و `ok:true`.
5. **جرب تسجيل دخول** بحسابك — لو دخل، يبقى القاعدة والجلسات سليمة 100%.
6. حوّل الدومين/الـ DNS للمضيف الجديد → اقفل القديم.

## 🖥️ نسخة الـ VPS (الاستقلالية الكاملة)

على أي VPS بـ Docker (Hetzner/Contabo/أي حد — ~$5): نفس الصندوق بيشتغل.
نقطتين بس:
- لو عايز القاعدة **محلية على نفس الجهاز** (أسرع وضع ممكن): غيّر
  `EF_DATABASE_ENGINE=sqlite` + وفّر قرص دائم + `EF_STORAGE_DURABLE=1` —
  شغّالة ومُختبرة (إثبات: السيرفر قام واشتغل بالكامل بدون أي خدمة خارجية في
  اختبار محلي). تفاصيل نقل الداتا نفسها في `04-MOVE-DATABASE.md`.
- حط NGINX/Caddy قدامه للـ HTTPS.

## 📱 نقطة العنوان المخبوز في التطبيق (مهمة جدًا)

التطبيق بيكلم السيرفر على العنوان اللي اتخبز وقت بناء الـ APK
(`EF_BASE_URL` — الافتراضي `https://elforma.onrender.com`).

- **لو غيّرت الدومين:** لازم APK جديد بـ `--dart-define=EF_BASE_URL=الجديد`
  والمستخدمين يحدّثوا.
- **الحل الأنضف:** امتلك دومين خاص (مثلًا `api.elforma.app`) ووجّهه لأي مضيف —
  كده التنقلات المستقبلية = تغيير DNS بس، والتطبيق مابيتأثرش خالص.

## الجلسات والأمان أثناء النقل

- الجلسات **بدون حالة** (توكنات HMAC موقعة) — مفيش جدول جلسات يتنقل.
  كفاية إن `EF_SECRET` يفضل ثابت وكل المستخدمين يفضلوا مسجلين عادي.
- قفل محاولات الدخول الفاشلة متخزن في القاعدة (`auth_lockouts`) — بيتحرك معاها.
