# 🔧 الصيانة اليومية — النشر، المراقبة، الرجوع، الأخطاء

## النشر اليومي (الدورة العادية)

```
عدّل الكود → ارفع على GitHub (main) → Render بيعمل deploy لوحده
→ GitHub Actions بتبني APK جديد لوحده (workflow: بناء تطبيق الفورمة الأصلي)
```

بعد كل deploy اتأكد من 3 حاجات (دقيقة واحدة):
1. `/api/health` → `ok:true` و `engine:"turso-remote"`
2. لوجز Render → `[db] adapter: turso-remote` ومفيش أسطر حمرا
3. سجّل دخول من التطبيق وافتح صفحة أو اتنين

## الحراس: الاختبارات

- **محليًا:** `npm run test:all` — بيشغّل الـ 61 اختبار كلهم
- **تلقائيًا:** الـ CI بيشغّلهم مع كل push — لو واحد وقع، الـ APK مابيتبنيش
- **اختبار الأداء:** `node tools/load-test.js` — أرقام حقيقية في أي وقت

## المراقبة بدون فلوس

### 1) منبه النبض (اتضاف)
`.github/workflows/uptime-pulse.yml` — GitHub بتفحص `/api/health` كل ~14 دقيقة.
لو الموقع وقع → إيميل فشل فورًا. (ميزة جانبية: بيخلي النسخة المجانية صاحية
في حدود الحصة المجانية 750 ساعة/شهر.)

### 2) لوحة مؤشرات التشغيل (اتضافت)
افتح بحساب الأدمن: `GET /api/admin/ops` — بيرد:

| الحقل | معناه | إمتى تقلق |
|---|---|---|
| `uptimeSec` | السيرفر شغال بقاله قد إيه | لو بيصفر كتير = السيرفر بيقع ويعيد التشغيل |
| `memoryMb` | استهلاك الذاكرة | المجاني 512 — لو قربت من 450 فيه تسريب/ضغط |
| `enginePool.busy / queued` | عمال حساب الخطط | لو `queued` فضلت عالية = حسابات بتتزاحم |
| `bootstrapCache.hitRate` | نسبة إصابات الكاش | كل ما تبقى أعلى، السيرفر أريح |
| `db` | محرك القاعدة الفعلي | المفروض `turso-remote` |

## الرجوع لنسخة قديمة (Rollback)

لو deploy جديد طلع فيه مشكلة:
**Render → خدمة elforma → Deploys → اختار آخر deploy ناجح قديم → Redeploy.**
دقيقة وترجع. (عشان كده فشل الـ deploy مابينزلش الموقع أصلًا — القديم بيفضل شغال.)

## جدول الأخطاء الشائعة

| الخطأ في اللوج | معناه | الحل |
|---|---|---|
| `WalConflict` | محاولة replica على القاعدة الحالية | الحارس بيرجع remote لوحده — متعملش حاجة، ومتفعّلش replica |
| `engine_busy` | طابور حساب الخطط مليان (أكتر من 32) | ضغط لحظي — المستخدم يشوف «مشغول حاول بعد دقيقة». لو متكرر كتير: كبّر `ENGINE_POOL_SIZE` أو الجهاز |
| `engine_timeout` | حساب خطة عدّى 15 ثانية | نادر — بيانات بروفايل شاذة؛ شوف الـ requestId |
| `durable_database_required` | القاعدة مش دائمة والحماية بتمنع الإقلاع | اضبط Turso صح أو `EF_STORAGE_DURABLE=1` مع قرص دائم |
| `429` كتير لمستخدم واحد | الـ rate limit شغال ضده | طبيعي ضد العبث؛ لو مستخدم حقيقي متضايق، الحدود في `lib/rateLimit.js` |
| استعلامات بطيئة | فعّل `EF_PERF_HEADERS=1` مؤقتًا وشوف `Server-Timing` | دور على الـ endpoint اللي `sql;dur` فيه عالي |
