# إصلاح الأونبوردينج الأفقي مع الخط الكبير

الأساس: ElForma-CI-Layout-Fix.zip. اللوج المرفق أظهر 105 اختبارات ناجحة، اختبارًا واحدًا فاشلًا، وآخر متخطى. المتبقي هو brand_refresh_test.dart على 800×400 مع مضاعفة الخط. فحوص الكيبورد والمقاسات الصغيرة اجتازت هذا التشغيل المرفق.

السبب: Column داخل IntrinsicHeight حُسب له ارتفاع 700 بينما احتاج محتواه ارتفاعًا أكبر. عمود النص داخل ConstrainedBox(maxWidth: 400) كان يُسأل عن ارتفاعه بعرض الأب ناقص padding (512 عند عرض المحتوى 560)، ثم يُعرض بعرض 400. اختلاف التفاف السطور أدى إلى RenderFlex overflow، وإلى توقف التمرير قبل إظهار نهاية الوصف (439 مقابل الحد 303).

التغيير: mobile/lib/widgets/brand_onboarding_page.dart فقط. استبدال قيد عرض النص الداخلي بهوامش أفقية محسوبة: max(24, (عرض الصفحة - 400) / 2). الهوامش تؤثر على حساب الارتفاع الداخلي وعلى التخطيط الفعلي بنفس الطريقة. عرض النص المرئي يظل min(عرض الصفحة - 48, 400)، والصور والألوان والخطوط والزر كما هي. لا تغيير باختبارات Flutter أو GitHub أو الكيبورد.

دليل تنفيذ Flutter: RenderConstrainedBox.computeMaxIntrinsicHeight يمرر العرض لاستعلام الطفل دون تطبيق قيد العرض الداخلي:
https://api.flutter.dev/flutter/rendering/RenderConstrainedBox/computeMaxIntrinsicHeight.html

التحقق المحلي: نجح فحص الصياغة، وفحصا brand-experience-v5 وui-accessibility-contract. تحققت معادلة تطابق عرض النص على قيود 320 و360 و400 و448 و560. مقارنة ZIP أظهرت تعديل ملف تطبيق واحد فقط، بلا حذف.

لم يُشغّل Flutter هنا ولا تم بناء APK؛ نتيجة نجاح الاختبار المتبقي بعد هذا التغيير تحتاج تشغيل GitHub. أرقام 105/1 تخص اللوج الذي أرسله المستخدم قبل هذا الإصلاح، وليست نتيجة اختبار محلية جديدة.
