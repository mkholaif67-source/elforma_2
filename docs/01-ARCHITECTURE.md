# 🏗️ المعمارية ببساطة — إزاي التطبيق مبني

## الرسمة الكبيرة

```
📱 تطبيق Flutter (الموبايل)
      │  HTTPS + JSON (ملف mobile/lib/api.dart)
      ▼
🖥️  سيرفر Node.js واحد (server.js)
      │  بيوزّع الطلبات على ملفات api/*.js
      ├─► 🧠 عقل التغذية  (app/diet/js)     ── بيشتغل جوه vm معزول على السيرفر
      ├─► 💪 عقل التمرين  (app/workout/engine)
      ├─► 🗄️  قاعدة البيانات (lib/db.js)     ── SQLite محلي أو Turso سحابي
      └─► 🌐 الموقع ولوحة الأدمن (public/)
```

## أهم فكرة في التصميم: «العقل» منفصل عن «المواسير»

- **العقل** = محركات التغذية والتمرين (`app/diet/js` + `app/workout/engine`).
  دي المعادلات والقواعد والذكاء. **مابتتلمسش** في أي تعديل تشغيلي.
- **المواسير** = السيرفر والقاعدة والكاش (`api/`, `lib/`). دي اللي بتتحسن وتتنقل.

وميزة نادرة في مشروعك: **نفس ملفات محرك التغذية بتشتغل في المتصفح وعلى السيرفر**
(`lib/nutrition-engine-host.js` بيشغّلها جوه `vm`). يعني مصدر واحد للحقيقة —
مستحيل الموقع والتطبيق يطلعوا أرقام مختلفة، وفيه اختبار `parity` بيضمن ده.

## الفولدرات واحد واحد

| الفولدر/الملف | فيه إيه |
|---|---|
| `server.js` | بوابة السيرفر: كل طلب بيعدي من هنا (الأمان، الضغط، التوجيه) |
| `api/` | ملف لكل عائلة مسارات: `mobile.js` (أكبرهم — مسارات التطبيق)، `auth.js`، `pay.js`، `admin.js`... |
| `lib/db.js` | قاعدة البيانات: الجداول، الفهارس، الاستعلامات المحضّرة |
| `lib/persistence/` | حدود القاعدة — تبديل sqlite/turso من غير ما الكود يحس (تفاصيل في `04-MOVE-DATABASE.md`) |
| `lib/engine-pool.js` | worker threads — الحسابات التقيلة مابتجمّدش السيرفر |
| `lib/cache.js` + `lib/cache-redis.js` | طبقات الكاش (LRU في الذاكرة + Redis اختياري للمستقبل) |
| `lib/auth.js` | الجلسات: توكنات موقعة (HMAC) — مفيش قاعدة جلسات، وده بيسهّل النقل |
| `app/` | المحركات + لوحات الويب |
| `public/` | الموقع التسويقي + لوحة الأدمن (ملفات ثابتة) |
| `mobile/` | تطبيق Flutter كامل (شاشات، نماذج، خدمات) |
| `test/` | 61 اختبار آلي (الحراس) |
| `tools/load-test.js` | اختبار الحمل — قياس الأداء الحقيقي في أي وقت |

## رحلة طلب حقيقي: فتح التطبيق (bootstrap)

1. التطبيق يطلب `GET /api/mobile/bootstrap`
2. السيرفر يتحقق من التوكن (بدون قاعدة — التوكن موقّع)
3. يدور في **كاش bootstrap** (أضفناه) — لو موجود يرد فورًا
4. لو مش موجود: ~30 استعلام صغير → يجمّع كل حاجة → يخزنها → يرد JSON مضغوط gzip
5. أي كتابة بعد كده (وزن جديد، وجبة...) تمسح نسخة المستخدم من الكاش فورًا

## طبقات السرعة (الكاش) — كلها مقصودة ومتحكم فيها

| الطبقة | العمر | بتمسح إمتى |
|---|---|---|
| bootstrap (سيرفر) | 20 ثانية | فورًا مع أي كتابة للمستخدم |
| خطة التغذية (سيرفر) | 90 ثانية | فورًا مع أي تغيير |
| الكتالوجات الثابتة | 10 دقائق | محتوى شبه ثابت |
| نسخة الجهاز (التطبيق) | نفس اليوم | عرض فوري + تحديث صامت |
| طابور الكتابات أوفلاين | حتى رجوع النت | يتبعت تلقائيًا |

**القاعدة الذهبية اللي المشروع ماشي بيها:** الكاش للقراءات بس، وأي كتابة بتمسحه —
فمستحيل مستخدم يشوف داتا قديمة بعد ما يغيّر حاجة.
